# Code of conduct

This project started inside Neuromatch Academy, and we keep its standard: the
[NMA Code of Conduct](https://docs.neuromatch.io/p/vIfHFwWpiwsIOa/Code-of-Conduct) applies to everything
here — issues, pull requests, reviews and commit messages included.

Short version, in our own words.

**Assume competence.** Everyone on this team came from a different field and a different timezone. A
question that sounds basic in your discipline is often the sharpest one in someone else's.

**Critique the analysis, never the person.** "This comparison doesn't control for X" is the work.
"You didn't understand the method" is not. We spent the project revising our own claims downward; that
only works if disagreeing is cheap and safe.

**Attribution is not a formality.** If you build on someone's function, notebook or idea, say whose it
was — in the docstring, the notebook header or the commit message. See
[`AUTHORS.md`](AUTHORS.md) and the attribution rule in [`gammas/contributed.py`](gammas/contributed.py).

**Don't edit someone else's sandbox.** `sandbox/<name>/` belongs to that person. Open a pull request or
ask; see [`CONTRIBUTING.md`](CONTRIBUTING.md).

**Respect the data terms.** The HCP Data Use Terms bind every one of us. No subject-level files and no
real subject identifiers in anything committed to this public repository.

## If something goes wrong

Raise it with any member of the team directly, or open an issue if it concerns the repository itself.
While the Academy was running, the escalation path was the pod TA; that route closed with the course, so
between us it is a conversation among peers. Nobody here holds authority over anybody else.
